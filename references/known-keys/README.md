# Known / default / leaked signing-key database

`tools/secureboot-analyze.py` cross-references a boot image's **signing-key SHA256** (MCUboot KEYHASH
TLV, etc.) against the `*.json` files here. A match → the image is signed with a **publicly-available
key** (a repo test key, a vendor default, or a leaked key), so an attacker can forge a valid
signature: **authentication is void** (CRIT finding).

## Format
Each `*.json` is a flat map of `{ "<sha256-hex>": "<description>" }`:
```json
{
  "<sha256 of the DER/PEM public key>": "MCUboot repo test key root-rsa-2048.pem — DEFAULT, forgeable"
}
```

## Populate it yourself (no fabricated hashes ship here)
The hashes are deterministic but device/format-specific, so this DB ships **empty on purpose** — do not
guess hashes. Add real ones:
- **MCUboot** test keys: `mcuboot/root-*.pem` in the MCUboot repo. The KEYHASH TLV is `SHA256` of the
  key MCUboot imports (see `scripts/imgtool.py getpub` output); hash that and add it.
- **wolfBoot** example keys: `wolfBoot/*.der` generated by `keygen`.
- **Vendor defaults / leaked keys**: add as you encounter them in engagements.

Once populated, a signed image using any of these keys is flagged CRIT automatically.
